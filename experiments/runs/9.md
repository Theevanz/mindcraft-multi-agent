## Hang mechanism, fully traced (mineflayer-pathfinder source)

`goto()` resolves ONLY on goal_reached / path_update(noPath/timeout) /
goal_updated(different) / path_stop. A path that EXISTS but never
completes (movement stall, no failure event) hangs forever — exactly
the silent connected-idle signature. Run 8's `stop()` cure poisoned
via a STALE FLAG: `stop()` only sets `stopPathing=true`; if the pending
goto already settled, the flag sits until the NEXT goto's setGoal →
resetPath sees it → instant `path_stop` → "Path was stopped" on a
healthy nav. Chain of (timeout → stale flag → poisoned next nav)
explains run 8's collapse (placements halved).
The lib SANCTIONS abandonment instead: a new goto's setGoal emits
goal_updated ≠ old goal → old promise rejects GoalChanged, listeners
cleaned ("chaining waypoints"). So: abandon-without-stop is safe, and
the stale-flag path is never touched.
